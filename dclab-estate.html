Read the core as an absence. show running-config section bgp returns nothing on core1–core4. In the BGP view they are the only nodes with no arc touching them — every session terminates on an edge, and the core exists purely to switch labels between BGP next-hops it resolves through IS-IS-SR.

Two IGP domains, no redistribution. The DC is OSPF; the WAN/DCI core and AS 65001 each run their own IS-IS-SR. bl1 is the only node in two of them and it runs them side by side. Nothing leaks between them — reachability crosses on BGP with next-hop rewrite, and SR provides transport to whatever next-hop lands.

Service prefixes are kept out of the core IGP on purpose — this is the load-bearing bit. While 172.16.2.0/24 was in IS-IS, the core had a native route to it and forwarded plain IP hop by hop; the SR label plane was fully programmed and completely unused. Removing that one interface from IS-IS was the entire fix — EOS immediately resolved the BGP route over the SR tunnel with no extra configuration:

B I 172.16.2.0/24 [200/0] via 10.0.0.6/32, IS-IS SR tunnel index 2 → label 900006

and the traceroute turned into core1 <MPLS:L=900006> → bl1 → mdrx. A BGP-free core is not a core that happens to run no BGP — it is a core with no route to the service at all, which is what leaves label switching as the only way through. Watch for the trap that produced this: netlab had put bl1's receiver-facing interface into both OSPF and IS-IS, so the prefix was being injected into both domains without a redistribute statement anywhere.

Ring metrics are deliberate, and now applied. core4↔core3 is 100 and the rest are 10, so for bl1 → asbr1 the path is core1→core2 and the alternate neighbour core3 has no loop-free path — its own route back to core2 runs through core1. No LFA exists, so TI-LFA has to build a repair to the post-convergence path and push a two-label stack rather than a single swap. Verified: with all four links at the default 10 the traceroute ECMP'd round both sides of the ring; at 100 it collapses to the single path asbr1 → core2 → core1 → bl1. Equal metrics would prove nothing.

Market data never touches the overlay. mktdata at the colo edge and mdrx in the DC both sit on dedicated routed segments — PIM-SSM inter-AS across the SR core, no VXLAN, no head-end replication, and the A/B disjointness stays available.
