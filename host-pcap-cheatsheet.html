Host & pcap cheatsheet

Receive-path diagnosis and packet analysis. Ordered by where you'd actually look, not alphabetically.

The receive-path ladder

Packets vanish at one of five stages. Walk them in order — each one rules out the layer below it. "No drops on the interface" only clears stage 2.

  1. Wire — did it arrive? capture at the NIC
  2. NIC — ring buffer, offloads · ethtool -S
  3. Kernel / NAPI — backlog, budget · /proc/net/softnet_stat
  4. Protocol — checksum, malformed · nstat
  5. Socket — app not draining · ss -uapmn

1 · Interface level

ip -s link show ens5RX/TX errors, dropped, overrun. First glance only.
ip -br addrOne-line-per-interface summary.
ethtool ens5Speed, duplex, link. Confirms negotiation.
ethtool -i ens5Driver and firmware version.

2 · NIC counters

ethtool -S ens5Everything the driver exposes. Pipe through grep -v ': 0$' to cut the noise.
ethtool -S ens5 | grep -iE 'drop|err|miss|discard|fifo'The lines that matter.
ethtool -g ens5Ring buffer size — current vs maximum.
ethtool -G ens5 rx 4096Raise the RX ring. First fix for bursty loss.
ethtool -c ens5Interrupt coalescing. Higher = fewer interrupts, more latency.
ethtool -k ens5Offloads. GRO/LRO coalesce packets and distort captures.
ethtool -l ens5Queue count — combined/rx/tx.
ethtool -x ens5RSS indirection table and hash key.

Names to know: rx_missed_errors and rx_no_buffer_count mean the NIC had a packet and nowhere to put it — the host wasn't draining fast enough. That's a host problem wearing a NIC counter's clothes.

3 · Kernel receive path

cat /proc/net/softnet_statOne row per CPU, hex, cumulative. Col 1 processed, col 2 dropped, col 3 time_squeeze.
watch -d -n1 cat /proc/net/softnet_statDiff it under load — absolute values are meaningless.
sysctl net.core.netdev_budgetPackets per NAPI poll. Raise if time_squeeze climbs.
sysctl net.core.netdev_max_backlogQueue depth per CPU. Raise if col 2 climbs.

Even spread across rows in col 1 is your RSS health check. One hot row means a polarised hash or a single active queue.

4 · Protocol counters

nstat -azAll counters, absolute. Without -a it shows deltas since last run — often what you want.
nstat -az | grep -iE 'rcvbuf|inerr|drop|prune|collapse'The interesting subset.
netstat -suUDP summary — receive buffer errors, packet receive errors.
netstat -stTCP — retransmits, out-of-order, listen drops.
cat /proc/net/snmpRaw source for the above.

UdpRcvbufErrors is the market-data gap counter. It means the socket buffer overflowed — the network delivered, the application didn't collect. Nothing upstream is at fault.

5 · Socket level

ss -uapmnUDP, all, process, memory, numeric.
ss -tapmnSame for TCP.
ss -tinTCP internals — cwnd, rtt, retrans, pacing rate.

The skmem:(r,rb,t,tb,f,w,o,bl,d) block: r = bytes queued now, rb = buffer size, d = drops on this socket. r riding near rb means the app is losing the race.

sysctl net.core.rmem_maxCeiling for SO_RCVBUF. Apps asking for more are silently capped.
sysctl net.core.rmem_defaultDefault, usually 212992 (~208 KB).
sysctl net.ipv4.tcp_rmemmin / default / max for TCP autotuning.

6 · Interrupts, affinity, NUMA

grep ens5 /proc/interruptsOne line per queue, counts per CPU. Two non-zero CPUs on a row = the IRQ has moved.
cat /proc/irq/<N>/smp_affinity_listWhich CPUs that IRQ may land on.
echo 3 > /proc/irq/<N>/smp_affinity_listPin it. Stop irqbalance first or it'll be undone.
systemctl stop irqbalanceRequired before any manual pinning is stable.
cat /sys/class/net/ens5/device/numa_node-1 = unknown, typical in a VM. Real value only on metal.
lscpu | grep -i numaNode count and CPU ranges.
numactl --hardwareFull topology and inter-node distances.
taskset -c 4 ./appPin the process to a core.
chrt -f 80 ./appReal-time FIFO scheduling.

7 · Live observation

sar -n DEV 1Per-second interface throughput.
mpstat -P ALL 1Per-CPU, including %soft — softirq load, i.e. network processing.
pidstat -w -p <pid> 1Voluntary vs involuntary context switches.
perf top -e cyclesWhere CPU time is going, live.
perf stat -e context-switches,cpu-migrations ./appMigrations are latency poison.
turbostatC-states and actual clock. Deep C-states add wake-up latency.

8 · tcpdump — capture

tcpdump -i ens5 -nn -e-nn no name/port resolution, -e show L2 header.
tcpdump -i ens5 -w cap.pcap -s0Full packets to file. -s0 = no snaplen truncation.
tcpdump -i ens5 -w cap-%H%M.pcap -G 60 -W 10Ring buffer: 60s files, keep 10.
tcpdump -r cap.pcap -nnRead back.
tcpdump -i ens5 -nn --time-stamp-precision=nanoNanosecond timestamps.
tcpdump -i ens5 -nn -c 100 -q100 packets, quiet output.

Filters

host 10.1.1.1 · net 10.1.0.0/16Address and subnet.
port 4789VXLAN.
udp and dst net 224.0.0.0/4All multicast.
igmpMembership reports and queries.
vlan 1000Tagged frames. Position matters — filters after it apply inside the tag.
mplsLabelled traffic.
'tcp[tcpflags] & (tcp-syn|tcp-fin) != 0'Connection setup and teardown only.
'tcp[tcpflags] & tcp-rst != 0'Resets.
'ip[6:2] & 0x1fff = 0'First fragment only.
less 100 · greater 1400By packet size.

Offloads distort captures. With GRO/LRO on, tcpdump sees one huge segment that never existed on the wire. Turn them off before capturing for MTU or reordering work: ethtool -K ens5 gro off lro off tso off gso off

9 · tshark — analysis

tshark -r cap.pcap -q -z io,stat,1Throughput per second.
tshark -r cap.pcap -q -z conv,tcpConversation table, sorted by bytes. Finds the elephant.
tshark -r cap.pcap -q -z expertWireshark's own warnings — retransmits, out-of-order, resets.
tshark -r cap.pcap -Y 'tcp.analysis.retransmission'Retransmits only.
tshark -r cap.pcap -Y 'tcp.analysis.out_of_order'Reordering — the one that looks like loss and isn't.
tshark -r cap.pcap -Y 'tcp.analysis.zero_window'Receiver told the sender to stop. App-side stall.
tshark -r cap.pcap -T fields -e frame.time_epoch -e ip.src -e udp.dstportFields to columns, for feeding awk or a spreadsheet.
tshark -r cap.pcap -Y 'ip.ttl < 5'Loop hunting.
tshark -r cap.pcap -d udp.port==4789,vxlan -Y vxlanForce the VXLAN dissector on a non-standard port.
editcap -c 10000 big.pcap split.pcapSplit an unmanageably large capture.
mergecap -w all.pcap a.pcap b.pcapMerge captures from two points, timestamp-ordered.

10 · Market data in a capture

UDP has no sequence number. Gaps can only be proven from the exchange protocol's own field in the payload — MoldUDP64 sequence, CME MDP MsgSeqNum. Without the right dissector you cannot see a gap at all.

tshark -r feed.pcap -Y 'moldudp64'Nasdaq-family framing.
tshark -r feed.pcap -T fields -e moldudp64.sequenceSequence to stdout — diff it to find the gap.
tshark -r feed.pcap -q -z io,stat,0.001Millisecond bins. Microburst hunting.
tshark -r feed.pcap -Y 'igmp'Did the receiver actually join, and when.

The decisive question: capture at the receiving NIC. A gap present in that capture was lost upstream — network. A gap the application reports but the capture doesn't show was lost between NIC and app — go back to softnet_stat and UdpRcvbufErrors.
